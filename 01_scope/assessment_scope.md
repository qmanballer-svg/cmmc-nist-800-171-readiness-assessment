# Assessment Scope

## Assessment target

This portfolio simulates a **CMMC Level 2 readiness assessment** of the Falcon Ridge Defense Components (FRDC) CUI enclave.

The goal is not to certify the fictional organization. The goal is to demonstrate how a GRC practitioner would define scope, gather evidence, evaluate controls, document findings, analyze risk, and drive remediation.

## In-scope assets

The simulated assessment boundary includes assets that process, store, or transmit CUI, plus security-protection assets that protect the enclave.

### CUI assets

- 52 managed Windows 11 engineering / program-management endpoints.
- 8 enclave servers / virtual workloads.
- Approved CUI file repositories and collaboration services.
- Approved printers / scanners used for CUI workflows.

### Security-protection assets

- Microsoft Entra ID tenant configuration supporting enclave access.
- Microsoft Intune configuration used to manage enclave endpoints.
- Microsoft Defender for Endpoint security controls and telemetry.
- Microsoft Sentinel workspace and related log sources.
- Firewalls, VPN gateways, network-security controls, and supporting management interfaces.
- Vulnerability-management tooling used to assess in-scope assets.
- Backup infrastructure supporting CUI systems.

### People and processes

- 65 authorized enclave users.
- IT administrators with enclave privileges.
- Security Operations, IAM, Network Security, GRC, Facilities, and HR control owners.
- Policies, procedures, training, incident response, risk management, and change-management processes that support the enclave.

## Out-of-scope assets

The following simulated assets are excluded because they do not process, store, or transmit CUI and do not provide security protection to in-scope CUI systems:

- public marketing website;
- public social-media accounts;
- unrelated corporate sales systems;
- guest wireless network;
- general employee devices not authorized for CUI;
- isolated manufacturing equipment with no connectivity or security-support relationship to the CUI enclave.

## Boundary assumptions

1. CUI is restricted to approved enclave workflows.
2. Corporate users outside the enclave cannot access CUI repositories.
3. Remote CUI access requires organization-managed devices and controlled VPN access.
4. Security Protection Data generated by the security stack is treated as sensitive and included in the assessment boundary where appropriate.
5. External service providers that provide security functions or store/process CUI would require evidence adequate to support the applicable assessment objectives.

## Assessment criteria

The control matrix uses the **110 CMMC Level 2 security requirements aligned to NIST SP 800-171 Rev. 2**.

Assessment methods follow the NIST SP 800-171A model:

- **Examine** relevant artifacts.
- **Interview** responsible personnel.
- **Test** mechanisms or processes when appropriate.

Each requirement receives one of the official CMMC findings:

- `MET`
- `NOT MET`
- `NOT APPLICABLE`

A requirement is not treated as MET merely because a policy states that the organization intends to perform an activity. Evidence must support applicable assessment objectives.
